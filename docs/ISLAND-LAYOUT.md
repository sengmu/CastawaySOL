## 开局设计目标

玩家醒来后，近景看见海难残骸与少量漂流资源；中景有椰树和可进入内陆的缺口；远景露出可探索地标。第一个镜头只承担求生方向，不展示完整成熟聚落。

主岛采用环线探索：南岸求生 → 西南营地 → 西部资源林 → 中央未来建设区 → 东侧溪流 → 东北高台 → 返回营地。支线可绕行，关键路线不依赖碰运气或穿模型。

不要直接把整条海岸改成大型沙滩。先在出生附近形成局部自然浅湾，草沙交界要有变化，同时同步碰撞与地表高度。生存点距离建议10–20米提供一次新反馈，最终以实际移动速度和视野验证。

## 建议开局流程

1. 醒来：确认海难处境，看到漂流物，学移动与拾取。
2. 沿湾采集：获得少量木材；附近椰树提供第一份食物/补水，记录真实行为。
3. 找到营地：从自然缺口到B区，修复营火和简易床位。
4. 采集林/水源：两条短支路分别解决工具和淡水，返回营地制作。
5. 修复通讯：由高台/漂流箱线索引导，不直接通关。
6. 收到求救：到G区准备木筏与补给，首次出航救援；回来扩容。

基础幸存者可在主岛救助教学中出现，但初始不同时安排多名悠闲居民。具体人物映射沿GAMEPLAY剧情衔接规则实施，避免造船和救援互相依赖。

## 必须统一的功能坐标

营地移动时同步：帐篷、程序营火、默认家具营火（避免两套重叠）、烹饪/睡眠交互、StorySystem的营地判断、任务提示与导航。资源移动同步掉落地表高度。SOS移到真实海岸，木筏放到出航湾，并同步main.js的情境距离判定。
码头应添加真实甲板可走面与连接处；行走范围不能简单整体放大到海里，应允许明确的码头甲板通道。
水道视觉、喝水/灌水判定、桥面高度和两岸碰撞使用一致数据，避免用未生效的riverPoints规划。

## 实施次序

1. 建立统一场景布局配置，先记录当前值；渲染、交互、剧情复用，避免只改模型位置。
2. 完成A/B/C区域：短路线、地表与资源来源；成熟装饰和居民按成长阶段出现。
3. 完成溪流、码头、SOS/木筏的视觉与功能对齐。
4. 用建设预留区承接生产，不急于重做全岛轮廓。
5. 再细化高台、遗迹和邻岛。

验收：从出生到营地、水源、资源林、码头均有连续可走路径；关键操作在实际物体旁触发；新存档不会自动完成采集；保存加载不重新刷固定资源；电脑和手机横屏实际检查构图与遮挡。先完成小区域，再增加内容密度。
