# 实施路线与验收

2026-10-31。以下全部为规划，不代表已完成；按依赖推进，不承诺日历工期。

## P0 求生流程

核查资源来源、地图可达性、配方与烹饪，整理ID清单；再移除过多开局赠品。任务记录真实行动，禁止初始条件跳关；移除收音机/木筏合成直接通关，合并重复结局规则。明确背包、生存、剧情、世界存档范围和schema迁移，失败不覆盖旧数据。
验收：新存档可完成采集、进食、补水、营地、制作，没有自动跳过和资源死锁；刷新后实际保存行为已验证。

## P1 单岛经营

漂流打捞、储物、建筑成本与预览、净水、首个救援、床位和一个真实生产岗位，显示供需。
验收：打捞→建设→生产→消耗→扩建闭环可玩，居民工作可见；取消/失败/重复输入不复制资源或重复扣费。

## P2 小群岛

一座主岛、木材岛、矿石岛；海图、补给准备、出航切场景、前哨归属、回运与家园扩建。
验收：完整往返、归属和资源一致；固定资源不能重复刷取；实际测量手机性能和载入。

## P3 小规模合作

建议2–4人，具体待确认。先定义访客、成员权限和物品归属，再选服务端方案。实现身份、权威库存建筑、房间进出、移动交互同步、重连、并发操作。
验收：两个独立真实客户端共同修改同一世界并保持一致，重连保留数据，客户端不能伪造有效库存。

## P4 争夺岛

独立争夺场景、占领点、结束条件，权威战斗、复活撤离、匹配保护、收益损失规则。
验收：真实客户端完成整局，正确处理掉线与重复领奖。再考虑海战、护送、联盟。

## 工程要求

UI显示系统状态，不自行结算胜利。逐步拆分UIManager中的物品、配方、HUD、弹窗，整理重复覆盖CSS。保留存档并设计版本迁移。每轮报告改动、实际验证与限制，更新HANDOFF。
验证重点：新存档、缺材料、重复点击、取消建造、切场景、刷新和重连。构建不替代运行与视觉验收。
暂不进入首版：无缝大型海洋、大规模海战、联盟城战、抽卡、复杂情绪、离线死亡、真实NFT经济。后续另行决策。

## 剧情衔接实施与额外验收

P0保留求生第一章，建立主线/发展/支线目标分类，取消制作即通关。
P1接入主岛基础救助、供水与分工，核对人物职责。
P2加入修复通讯收到邻岛求救、首次航行救援、回营扩容、资源岛开发。首次出航准备允许手动完成，不能依赖尚未救回的人。
后期再保留可选逃脱结局与继续经营入口。
验收：支线不误推主线；发展目标可选择；首次航行无循环依赖；净水首次建造与扩容不重复触发；阶段结算不清空家园。
