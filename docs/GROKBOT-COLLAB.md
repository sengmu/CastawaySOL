# CastawaySOL × Grok Bot 协同约定

定版：2026-11-03，用户批准。一句话：**群管创意与评审，主控管生产与验收，仓库是唯一真源。**

## 分工

| 层 | 谁 | 干什么 | 不干什么 |
| --- | --- | --- | --- |
| 创意与评审层 | Grok Bot「CastawaySOL」群（Game Art Director、Director 等）＋用户 | 出设计稿、定美术/内容规范、审图审片、给修改意见；用户在群里拍板 | 不改代码、不提交、不发布 |
| 生产与验收层 | 主控 Muse | 回收群里定版 → 落成仓库文件 → 派 Codex / Blender / Tripo 生产 → 跑测试与截图验收 → 验收图回贴群里复审 → 提交推送 → 向用户汇报 | 不替用户拍板设计、不跳过复审直接进包 |

## 任务安排接口（2026-11-03 用户指定）

- **任务安排统一经 Projects Manager**：它是 Grok Bot 里的项目经理 Bot，负责排任务、配班子、维护 Notion 看板、盯无人认领或被卡住的任务；用户是拍板人。
- 主控与 Projects Manager 在其会话里**直接对话对接**（用户 2026-11-03 授权）：PM 把需要真实生产/核实的任务与验收标准发给主控，主控做完把提交号、测试结果、截图路径回给 PM。
- PM 已确认接受本约定的分工与三条对接规矩，并会让 Webby 拉取本文档备查（2026-11-03 12:5x 其会话内回复）。

## 交接流程

1. 用户在群里丢需求或拍板；Bot 产出设计稿 / 规范 / 评审意见。
2. 主控经 NUC 桌面读取群消息（默认工具 agent-desktop，走无障碍树 ref 操作；无障碍树缺失时才回退截图找坐标），发送后用存档回读核验，不靠截图猜。
3. 主控把定版结论落成仓库文件才算定版：设计稿进 `docs/model-sheets/`，规范进 `docs/*-spec.md`，评审记录进 `docs/qa/`。聊天记录不是真源，会刷走、也会让两地分叉。
4. 给 Bot 派活走已验证的法子：在消息里贴文件路径，Bot 自己取文件；不拖放、不贴图赌它看见。
5. 生产完成后，验收材料（并排对照图、实机截图）回贴群里给对应 Bot 复审；复审过了才进包、才提交。
6. Bot 的一切产出先经主控核验才用。花钱、对外发布、账号安全类事项仍由用户批准，Bot 与本约定都不放行。

## 两地同步

- 中枢 = GitHub 私有仓 `sengmu/CastawaySOL`；家里 NUC 与公司电脑都围着它推拉（NUC 走 443 端点，公司走 SSH）。
- 离开一地前 commit + push，到另一地先 pull 再开工；未提交的改动不跟人走。
- 用户说「收工 / 开工」，主控代办对应机器的推 / 拉与状态核验。

- 版本号归公司线所有，主控不单方面升版。
- 一个构建算完成，只认用户在 Seeker 真机上能触摸游玩。
